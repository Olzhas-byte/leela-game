## 1. Главный архитектурный принцип

**Логика — в коде. Смысл — у LLM.**

Системный промт ведущего прямо запрещает: «не придумывай клетки», «не меняй названия», «не меняй
расположение змей и стрел», «не путай положение игрока». LLM ненадёжен в арифметике состояния и
склонен к галлюцинациям клеток. Поэтому:

- **Код владеет состоянием игры:** бросок кубика, вычисление позиции, проверка змей/стрел, имена
  клеток, правила входа и финиша, история ходов.
- **LLM получает уже готовый, посчитанный результат хода** (номер и название клетки, тип события:
  обычный ход / змея / стрела / финиш) и **только трактует** его по канону «Лилы» и относительно
  намерения игрока.
- LLM **никогда** не сообщает игроку число, позицию или переход — это делает UI на основе данных кода.
  LLM выдаёт только текст трактовки.

Это убирает целый класс багов и делает игру воспроизводимой.

## 2. Технологический стек

- **Фреймворк:** Next.js (App Router) + TypeScript — фронтенд и API-роуты в одном приложении,
  хорошо деплоится на Railway из GitHub.
- **Стили:** Tailwind CSS (спокойная, «тёмная/глубокая» эстетика под тон игры).
- **БД/ORM:** PostgreSQL (Railway plugin) + Prisma.
- **Авторизация:** Auth.js (NextAuth) — credentials (email + пароль) или magic-link. Сессии в БД.
- **LLM-клиент:** `openai` SDK, направленный на endpoint GLM (`baseURL` + `apiKey` из env).
  GLM 5.2 предоставляет OpenAI-совместимый Chat Completions со стримингом.
- **Стриминг ответа:** Server-Sent Events / ReadableStream из API-роута во фронтенд.

## 3. Модель данных доски (канон «Лилы»)

Доска — 72 клетки. Это **статические данные**, единый источник правды:
`src/game/board.ts` (или `board.json`).

```ts
// Клетка
interface Cell {
  number: number;        // 1..72
  name: string;          // классическое название (RU + опц. санскрит/EN)
  sanskrit?: string;
  meaning: string;       // краткий символический смысл (опора для LLM, не показывается дословно)
  shadow: string;        // теневая сторона / ловушка
  plane?: string;        // план сознания (ряд доски), для визуализации
}

// Переход (змея или стрела)
interface Transition {
  type: 'arrow' | 'snake';
  from: number;
  to: number;
  virtue?: string;       // для стрелы: качество, дающее подъём
  lesson?: string;       // для змеи: неусвоенный урок
}
```

### ✅ КАНОН ДОСКИ ЗАФИКСИРОВАН (готово)
Канон уже занесён в [`src/game/board.ts`](src/game/board.ts) и неизменен:
- **72 клетки** (RU-названия + санскрит + краткий смысл + теневая сторона + ряд 1–8) —
  по версии Хариша Джохари (сверено по leelaroom.com и др.).
- **Стрелы:** 10→23, 17→69, 20→32, 22→60, 27→41, 28→50, 37→66, 45→67, 46→62, 54→68
- **Змеи:** 12→8, 16→4, 24→7, 29→6, 44→9, 52→35, 55→3, 61→13, 63→2, 72→51
- **Цель:** клетка 68 «Космическое сознание».
- В файле есть `validateBoard()` — самопроверка целостности (72 клетки, корректность переходов).

> Если у заказчика появится оригинальная доска из книги Джохари — менять значения только
> здесь, в `board.ts`, в одном месте. Sonnet эти данные НЕ генерирует и НЕ меняет.

## 4. Правила игры (детерминированные)

Реализовать как чистые функции в `src/game/rules.ts`. Заложить правила конфигурируемо,
т.к. версии слегка различаются:

1. **Вход в игру.** Игрок стартует «вне доски» (позиция 0). Чтобы войти, нужно выбросить **6** —
   тогда игрок встаёт на клетку 6. Пока 6 не выпала, ход не даёт продвижения (LLM может коротко
   прокомментировать «ожидание рождения», но без трактовки клетки).
2. **Дополнительный ход за 6.** Выпавшая 6 даёт право на ещё один бросок (по классике). Подтвердить,
   нужно ли это в MVP — заложить флаг `EXTRA_TURN_ON_SIX`.
3. **Движение.** Новая позиция = текущая + число кубика.
4. **Стрелы и змеи.** После перемещения проверить переход: если на клетке есть стрела/змея —
   мгновенно переместить в `to`. (Сначала стрелы/змеи, отдельной проверкой; на одной клетке не может
   быть и того и другого.)
5. **Финиш (клетка 68).** Чтобы завершить, нужно попасть **точно** на 68. При перелёте — правило
   «отражения»: лишние шаги отсчитываются назад от 68 (заложить флаг, т.к. варианты различаются).
   Достижение 68 = завершение партии (космическое сознание).
6. **После 68.** Партия закрывается; результат сохраняется в БД.

Все эти параметры — в одном конфиге `src/game/config.ts`, чтобы Sonnet не «зашивал» магию в логику.

## 5. Состояние игры и схема БД

### Игровое состояние (в коде / БД)
```ts
interface GameState {
  id: string;
  userId: string;
  intention: string;          // намерение игрока — НЕИЗМЕННО в течение партии
  status: 'awaiting_intention' | 'awaiting_entry' | 'in_progress' | 'finished';
  position: number;           // 0 = вне доски
  previousPosition: number;
  history: Move[];            // полная история ходов
  createdAt: Date;
  finishedAt?: Date;
}

interface Move {
  index: number;              // номер хода
  dice: number;               // 1..6
  diceSource: 'player' | 'auto';
  fromPosition: number;
  toPosition: number;         // позиция после движения и перехода
  landedBeforeTransition: number;
  transition?: Transition;    // если сработала змея/стрела
  cellNumber: number;
  interpretation: string;     // текст трактовки от LLM (сохраняем)
  createdAt: Date;
}
```

### Prisma-схема (минимум)
```
User       (id, email, passwordHash, createdAt)
Game       (id, userId FK, intention, status, position, previousPosition,
            createdAt, finishedAt)
Move       (id, gameId FK, index, dice, diceSource, fromPosition, toPosition,
            cellNumber, transitionType?, transitionTo?, interpretation, createdAt)
Session/Account  (по требованиям Auth.js)
```

**Важно:** намерение хранится в `Game.intention` и подаётся в КАЖДЫЙ запрос к LLM — ведущий
обязан помнить намерение всю партию.

## 6. Бэкенд: эндпоинты и интеграция с GLM

### API-роуты (Next.js route handlers)
- `POST /api/auth/*` — Auth.js (регистрация/логин/сессия).
- `POST /api/game` — создать партию (принимает intention + подтверждение честной игры).
  Валидация: без непустого намерения партия не создаётся (правило промта).
- `GET  /api/game/:id` — состояние партии + история (только владелец).
- `POST /api/game/:id/roll` — основной эндпоинт хода:
  1. Принимает `{ diceSource: 'player'|'auto', dice?: number }`.
  2. Если `auto` — сервер генерирует число 1..6 (криптослучайно).
  3. Детерминированно считает: вход/движение/переход/финиш (функции из `rules.ts`).
  4. Обновляет `GameState` и пишет `Move` (без интерпретации пока).
  5. Формирует контекст и **стримит** трактовку от GLM, по завершении сохраняет `interpretation`.
  6. Возвращает фронту: посчитанный результат хода (числа, клетка, тип события) + стрим текста.
- `GET  /api/games` — список партий пользователя (история/результаты).

### Интеграция с GLM 5.2
```ts
import OpenAI from 'openai';
const glm = new OpenAI({ apiKey: process.env.GLM_API_KEY, baseURL: process.env.GLM_BASE_URL });

const stream = await glm.chat.completions.create({
  model: process.env.GLM_MODEL,        // 'glm-5.2'
  stream: true,
  temperature: 0.7,
  messages: [
    { role: 'system', content: SYSTEM_PROMPT },          // промт ведущего (см. §7)
    { role: 'user',   content: buildTurnContext(state, move) }, // детерминированные факты хода
  ],
});
```
> Заложить таймаут, ретраи и graceful-фоллбэк (если LLM недоступен — показать сухой результат хода
> из кода и кнопку «повторить трактовку»).

## 7. Системный промт и формирование контекста хода

- **Системный промт** = промт ведущего «Лилы», предоставленный заказчиком (роль, правила, структура
  из 7 пунктов трактовки, блоки про змей и стрелы, стиль, запреты). Хранить в `src/llm/systemPrompt.ts`
  целиком, без изменений по смыслу.
- **Контекст хода** (`buildTurnContext`) — детерминированные факты, которые код подаёт LLM как
  «вот что произошло, дай трактовку»:

```
НАМЕРЕНИЕ ИГРОКА: "<intention>"
ИСТОРИЯ ХОДОВ (кратко): ход 1 → клетка X (...), ход 2 → ...
ПРЕДЫДУЩАЯ КЛЕТКА: <num> «<name>»
БРОСОК: <dice>
СОБЫТИЕ: <обычный ход | СТРЕЛА from→to | ЗМЕЯ from→to | ФИНИШ 68 | ожидание входа>
ТЕКУЩАЯ КЛЕТКА: <num> «<name>»
  символический смысл (опора): <meaning>
  теневая сторона (опора): <shadow>
  [для стрелы] качество подъёма: <virtue>
  [для змеи] неусвоенный урок: <lesson>

Задача: дай трактовку этой клетки строго по структуре из системного промта,
относительно намерения игрока. Не сообщай числа и позицию — это уже показано игроку.
```

Так LLM не считает арифметику и не выдумывает клетки — он получает выверенные данные из `board.ts`
и только раскрывает смысл. Имена/смыслы клеток из кода служат «рельсами» против галлюцинаций.

## 8. Фронтенд: экраны и UX-поток

Тон: спокойный, глубокий, без эзотерического «тумана» (как требует промт). Тёмная палитра,
много воздуха, медленные мягкие анимации, без геймификации/«вау».

### Экраны
1. **Вход/регистрация** (Auth.js).
2. **Старт партии:**
   - поле «Сформулируйте намерение» (обязательно, валидация непустоты);
   - чекбокс «Готов(а) играть честно» (обязателен);
   - кнопка «Начать» неактивна без обоих условий (отражает правило промта).
3. **Игровой экран** (основной):
   - **Доска 72 клеток** (8×9 змейкой) со змеями и стрелами; подсвечена текущая позиция;
     пройденный путь — мягким следом. (SVG для линий змей/стрел.)
   - **Лента ведущего** — диалог: трактовки клеток стримятся текстом по мере генерации.
   - **Панель хода:** «Бросаете кубик сами или сгенерировать число от 1 до 6?» →
     варианты: ввод своего числа (1–6) ИЛИ кнопка «Сгенерировать». Анимация кубика.
   - **Намерение** всегда видно сверху (как якорь).
4. **Завершение** (клетка 68): экран итога партии, краткое резюме пути, сохранение в историю.
5. **История партий:** список прошлых игр с намерениями, путями и финалами.

## 11. Риски и что подтвердить до старта

1. **Канон доски** — главный риск. Без выверенных названий и координат змей/стрел нарушается
   правило промта «не придумывай клетки». Сверить с источником Джохари до Фазы 2.
2. **Точные правила входа/финиша/доп.хода** — варианты различаются; вынесены в `config.ts`.
3. **GLM 5.2 API** — подтвердить `baseURL`, точный id модели, формат стрима и лимиты; убедиться,
   что модель стабильно держит русский и длинный системный промт. Если стрим несовместим —
   фоллбэк на нестриминговый ответ.
4. **Стоимость/таймауты LLM** — трактовка длинная; заложить таймауты, ретраи, ограничение длины.
5. **Приватность** — намерения и трактовки личные; доступ к партии только владельцу,
   пароли — хэш (bcrypt/argon2).
